# Where the committed binary assets came from

Every binary file under `assets/` is generated by a script this repository runs, and a lint test
checks that the committed copy is still what the script produces. The rule and this file's shape
are atlas-engine's (its `assets/source/PROVENANCE.md`), where these assets lived until M27.

| File | Generator | Licence |
|---|---|---|
| `textures/chess_pieces.png` | `tools/gen_chess_textures.py` | GPL-3.0-or-later, as the script |
| `../mods/chess_opponent.wasm` | Atlas's `share/atlas/tools/build_mods.py --mods mods.json`, from `mod/*.c` | GPL-3.0-or-later, as the sources |

`chess_pieces.png` carries no compressed data: its deflate stream is written as stored blocks, so
the bytes are the script's alone and the check (`chess_textures_current`) can compare them.

`chess_opponent.wasm` is freestanding C compiled by clang and linked by wasm-ld of LLVM 23
(atlas-engine ADR-0023), so its bytes are the compiler's. Its check (`chess_mods_built_current`)
compares every input's hash, the guest header `atlas/script/atlas_mod.h` from the installed Atlas
included, and the committed module against `mods/chess_manifest.json` on any machine; rebuilds
wherever the toolchain exists; compares the rebuilt bytes only on the manifest's own toolchain;
and plays the rebuilt module and the committed one against themselves in this build's
`atlas_chess`, which must end in the same position with the same state hash.
