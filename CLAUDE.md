# atlas-chess — working rules

Chess on the Atlas engine, built only against an installed Atlas (atlas-engine ADR-0024). The
engine's own rules are in atlas-engine's `CLAUDE.md`; the ones below are the ones that bind here.
ADR and milestone numbers are atlas-engine's.

## The one rule this repository exists for

**Chess never patches the engine.** It includes only headers from the Atlas install prefix and
links only the exported `atlas::` targets. Something the engine should do differently is changed
in atlas-engine, released there, and reached here by moving the pin in `atlas.ref`. A copy of an
engine file, a private header path or a patched engine build here would make this repository
prove nothing, which is the only thing it is for.

## Commands

```sh
eval "$(python3 ../atlas/tools/sdk.py macos-debug | sed 's/^/export /')"   # the SDK, once
cmake --preset macos-debug
cmake --build --preset macos-debug
ctest --preset macos-debug                     # everything
ctest --preset macos-debug -L integration      # the whole program only
python3 tools/gen_chess_textures.py            # after changing the piece drawing
python3 "$ATLAS_PREFIX/share/atlas/tools/build_mods.py" --mods mods.json   # after changing mod/*.c
tools/tidy.sh macos-debug                      # clang-tidy over the C++, as CI runs it
```

## Moving the pin

`atlas.ref` names the atlas-engine commit this is built against, and CI checks that the binary
reports it. To move it: build and install the SDK at the new commit, update `atlas.ref`, and run
every test. **If the golden test fails**, the engine changed what a hash is or how a tick runs.
Decide whether that was meant, in atlas-engine, and say so; never change the constant here to make
it pass. If `chess_mods_built_current` fails on the guest header, the mod interface moved:
rebuild the opponent and read what changed.

## Rules carried over from the engine

- **`chess::sim` links `atlas::simulation` and nothing else**, and the build checks it (ADR-0018
  D3). The rules reach the engine through its simulation contract only.
- **A tick is: drain and apply commands, compute, commit, hash.** Nothing reaches the state except
  through a command. A handler that declines has changed nothing (ADR-0019).
- **The state is integers.** A float in it needs a recorded reason and a golden comparison.
- **Every string a person sees comes from the catalogue by a key** in `src/chess_text_keys.hpp`,
  resolved against `assets/source/strings/chess.en.json` beside the engine's table (ADR-0016,
  ADR-0018). Log lines and the usage block are not localised.
- **The opponent is freestanding C**, compiled by clang and wasm-ld of LLVM 23 through Atlas's
  `build_mods.py`, and committed with its manifest (ADR-0023). It does a fixed amount of work per
  tick, counted in moves, never in time.
- **Every committed binary asset is generated by a script with a check**, listed in
  `assets/source/PROVENANCE.md`.
- Warnings are errors. `-ffp-contract=off` and `/fp:precise` are set in `cmake/ChessBuild.cmake`,
  copied from the engine's flags, because an installed package does not carry them.
- Every file starts with an SPDX identifier: `GPL-3.0-or-later`.

## Before pushing

Build Debug and Release, run every test, check formatting with clang-format 23 over the C and C++
(`clang-format --dry-run --Werror`), and commit only what you meant to. Push only on the owner's
word.
